# Wellnest — class collaboration starter

A responsive, static healthcare landing-page scaffold for students to practise collaborating with Git and GitHub. The page is built with semantic HTML and plain CSS; there are no build tools or dependencies.

## Project structure

```text
Class-collab/
├── index.html          # Starter landing page and section structure
├── css/
│   └── style.css       # Design tokens, components, layout, and responsive styles
├── js/
│   └── main.js         # Reserved for a later JavaScript lesson
├── images/
│   └── .gitkeep        # Add approved image assets here
├── CONTRIBUTING.md     # Team workflow and contribution checklist
├── .gitignore
└── README.md
```

## Open the page

No install step is required. Clone the repository and open `index.html` in a browser. For a local development server, VS Code's Live Server extension is one option.

```bash
git clone https://github.com/lordvic4real/Class-collab.git
cd Class-collab
```

The current starter is intentionally partial: it contains a header, hero, introduction, three care cards, a simple how-it-works section, contact call to action, and footer. Students can extend it with additional sections, refine the visuals, and add approved assets. JavaScript is intentionally deferred.

## Team workflow

1. Start from the latest shared `main` branch.
2. Create a branch for one small task (for example, `feature/testimonial-section` or `fix/mobile-spacing`).
3. Make and preview your change at desktop and mobile widths.
4. Commit with a clear message and push your branch.
5. Open a pull request into `main`. Describe the change, include screenshots for visual changes, and ask a teammate to review it.
6. Make requested changes in the same branch. Merge only after review and any checks required by your class.

See [CONTRIBUTING.md](CONTRIBUTING.md) for commands and collaboration guidelines.

## Design notes

The colour palette and editorial-style layout are a starting point, not a finished product. Replace placeholder brand/content as your team decides, keep the HTML accessible, and avoid adding personal or sensitive information to the repository.
